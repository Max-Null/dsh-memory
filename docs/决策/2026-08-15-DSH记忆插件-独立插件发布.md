## 一、背景

要把 oc-plus 的记忆能力带给 DeepSeek Harness 社区。最初误判为「改 DSH 源码」——fork DSH、把 3 个包塞进 `packages/memory/`、注册 tsconfig 聚合。经纠正：DSH 的哲学是「**一切皆插件**」，插件应是独立仓库、声明 `name`/`inject`/`apply`、由 Loader 从 `cordis.yml` 加载，不改源码。

## 二、关键决策

1. **独立插件，不改 DSH 源码**：一个包 `@max-null/dsh-memory`，依赖 npm 上的 `@deepseek-ai/dsh-*`（peer，`>=0.0.1-rc.1`），用户在 `cordis.yml` 加一行即可。
2. **两层物理分存**：`global` 记忆 → `$DSH_HOME/storages/`；`project` 记忆 → 项目文件夹 `<cwd>/.dsh/storages/`，随 `git` 分享给协作者。
3. **BM25 + 明文，拒绝向量**：明文可观测、可版本控制、可 git 分享；向量是"无法观测、无法修复的静默暗礁"。语义检索留 v2，以"可观测 + 可修复"为门槛。
4. **人工闸门**：`memory_save` 只写 `suggested`，`setStatus` 是唯一提升路径——模型绝不自我提升。
5. **缓存安全**：固定指引进 system-prompt section（前缀稳定），`auto` 记忆进 context（append-only，带 `[memory:<id>]` 溯源）。

## 三、验证（全部实测）

- typecheck（严格）、vitest 单测、Loader 端到端、DSH 源码冒烟测试
- **真实模型回合**：模型调 `memory_save` → 落盘 → 跨会话 `memory_search` 召回 → `project` 命名空间落项目文件夹

## 四、踩坑记录（备查）

1. **patch 语法**：`--patch` 新增条目必须用 `insert:` 包裹，直接 `- id:` 会被当"补丁已存在条目"报 `entry not found`。
2. **模型不会自动用新工具**：第一次让模型"记住"，它只回文字"记住了"却不调 `memory_save`——印证"untrained models under-use any new tool"，需提示词明确引导。
3. **插件自提供的服务用 `ctx.get()`**：插件自己注册的 `ctx.memory` 不能走 `ctx.memory` 属性访问（报 `cannot get property without inject`），须用 `ctx.get('memory')`。
4. **域名正则**：storage 域名只允许 `[a-z][a-z0-9_]*`，`memory-project` 非法，须 `memory_project`。
