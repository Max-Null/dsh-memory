# 注入文本的严格插值防护：设计方案（2026-09-23）

> 状态：**设计待评审**（未实现）
> 关联：`src/index.ts`（`recallText`）、`src/injection.ts`、`test/injection-assembly.spec.ts`
> 外部对照：`third-party-plugins/dsh-auto-memory`（`src/prompt.ts` 的 `neutralizeBraces` 处理同一问题）

## 一、目标

让 `memory:recall` 注入的文本在 DSH 的严格插值下不可能抛错，同时保持记忆真相源与面板显示不变。

**非目标**：改存储格式、在写入侧过滤或改写用户内容、给注入文本追加转义说明、做 DSH 版本探测。

## 二、机制

DSH 0.1.5-rc.2 的 `renderPrompt` / `renderContextSections` 对每个 section 与 context 做严格 `{{variable}}` 替换：名字不匹配 `^[a-z][a-z0-9_]*$` 的引用抛 `malformed`，匹配但未注册的抛 `unknown`。**两者都抛错，不是原样保留。** 只有孤立的 `{{`（其后不再出现 `}}`）按字面文本放过。

用本机 `deepseek-harness/packages/core/system-prompt/lib/index.js` 的真实 `renderPrompt` 实测：

| 输入片段 | 结果 |
|---|---|
| 普通中文文本 | 通过 |
| `{{ count }}` | 抛 `malformed prompt variable reference` |
| `{{count}}` | 抛 `unknown prompt variable "{{count}}"` |
| `{{ variable }}` | 抛 `malformed` |
| 光秃秃的 `{{` 不闭合 | 通过（按字面文本） |

section 与 context 走同一条插值路径，行为相同。

## 三、可达路径与现状

`memory:recall` 是 context，文本由 `recallText`（`src/index.ts`）拼装。四条子路径都含**模型或用户写入的内容**：

| 子路径 | 内容来源 |
|---|---|
| `rendered.lines` | `deriveSummary(record.content)`——记忆正文首行 |
| `omittedNotice` | `deriveSummary(record.content, 24)`——被预算挡下的记忆正文 |
| `indexNotice` | `record.keywords`——记忆关键词 |
| `neighborNotice` | 子项目目录名（文件系统路径段） |

不构成触发源：`tool:memory`（`GUIDANCE`）与 `memory:self`（`SELF_DESCRIPTION`）是固定文本，`src/` 全目录 grep `{{` 无匹配。

**现状**：`$DSH_HOME/storages/memory.json` 与工作区的 project 记忆文件当前一处 `{{` 都没有，缺陷潜伏未触发。

**后果**：组装发生在模型调用之前，失败即该轮请求不成立；每轮重复即会话不可用，而模型无从自救——它改不了自己的记忆。这条完整链路未在真实会话复现，见 §七。

## 四、备选方案

| 方案 | 结果 | 取舍 |
|---|---|---|
| 写入侧拦截（`memory_save` 拒绝或改写含 `{{` 的内容） | 触发源在源头消失 | **否决**：记忆是明文审计窗口，改写污染真相源；拒绝则把宿主的插值实现细节泄漏给用户 |
| `injectionLine` 内中和 | 覆盖注入行 | **否决**：该函数的契约是「与面板预览完全一致」，面板会显示被改写的内容；且漏掉 omitted / index / neighbor 三条 |
| 存储读取处中和 | 覆盖全部读路径 | **否决**：同写入侧，污染真相源 |
| **`recallText` 出口中和** | 四条子路径的唯一汇合点 | **选定**：一处覆盖全部，将来新增子行自动纳入 |

## 五、机制设计

### 5.1 中和函数（`src/injection.ts`）

```ts
/**
 * 消除文本里的字面 `{{`：DSH 的严格插值把 `{{name}}` 当变量引用，未注册即抛错、
 * 炸掉该会话全部模型请求。循环替换直至稳定——单遍 `replaceAll` 对 3 连以上左花括号
 * 会残留：`{{{{a}}}}` 单遍得 `{ {{ {a}}}}`，仍含 `{{`。实测 1..1000 连最多 2 轮收敛。
 */
export function neutralizeBraces(text: string): string {
  let result = text
  while (result.includes('{{')) result = result.replaceAll('{{', '{ {')
  return result
}
```

实测记录（真实 Node 运行本函数）：

- 单遍残留：`{{{{a}}}}` → `{ {{ {a}}}}`（仍含 `{{`）；`{{{{{{` → `{ {{ {{ {`（仍含 `{{`）。**单遍不够，循环是必需的。**
- 收敛轮数：1 连 0 轮、2 连 1 轮、3..1000 连 2 轮，输出均不含 `{{`。
- 普通文本：`a {{ count }} b` 单遍即净。

### 5.2 收口点（`src/index.ts` 的 `recallText`）

```ts
return neutralizeBraces(parts.join('\n'))
```

放在 `parts.join` 之后而不是各子行内部：四条子路径在这里唯一汇合，一处即全覆盖；将来新增子行不必记得各自中和。

代价是注入副本与面板预览在 `{{` 一处显示不同（`{{` → `{ {`）。面板保留原文是有意的——它是给人看的审计窗口，显示被改写过的内容会让人以为记忆本身被改过。语义损失限于拆开的花括号，模型仍读得懂。

### 5.3 不做的

- 不改写存储，不改面板，不给注入文本加提示语。
- 不引入 DSH 版本探测：`{ {` 在任何版本下都只是文本原文，而探测会把「当前部署是哪个版本」变成插件的负担。

## 六、验证

### 6.1 单元（`test/injection.spec.ts`）

`neutralizeBraces` 的边界：2 连、3 连（Mustache raw partial `{{{x}}}`）、4 连、50 连、1000 连的输出均不含 `{{`；无花括号的文本原样返回。

### 6.2 装配级（`test/injection-assembly.spec.ts`，复用既有 `setup` 与 `assembleFor`）

写入一条 content 含 `{{ count }}` 的常驻记忆，组装后：

1. `recallTextOf(assembly)` 不含 `{{`。
2. **`renderPrompt(assembly)` 不抛**——这才是验收判据，字符串断言只是辅助。该文件目前只导入 `SystemPrompt` 的默认导出，需要补 `renderPrompt` 的具名导入。
3. 反证：拿掉 §5.2 那一行调用，该用例必须失败——否则它没有测到东西。

## 七、复现证据与覆盖空白

**已在真实栈复现**（2026-09-23）。用本仓库 `test/injection-assembly.spec.ts` 同款的 setup（真 `Context` + 真 `Storage` + 真 `SystemPrompt` + 真 `ToolRegistry` + 本插件），经 `ctx.memory.remember()` 写一条常驻记忆并 `setInjected(id, true)`，再 `assemble()` 取 `memory:recall` 文本，最后喂给真实的 `renderContextSections`：

| 记忆正文 | 注入文本含 `{{` | `renderContextSections` |
|---|---|---|
| 用户偏好中文交流，本机用 PowerShell 7 | 否 | OK |
| 项目里 Vue 模板用 `{{ count }}` 做插值 | 是 | **抛 `malformed prompt variable reference`** |
| 写提示词时变量名写成 `{{footer}}` 的格式 | 是 | **抛 `unknown prompt variable`** |
| 这里的 `{{` 没有闭合，是字面文本 | 是 | OK（孤立左括号按字面放过） |

测量环境为 `@deepseek-ai/dsh-system-prompt@0.1.1-rc.2`（本仓库 devDependency）；同一行为在部署所用的 `0.1.5-rc.2` 上另行验证过——section 与 context 两条插值路径都会抛。注意 `renderPrompt()` 只处理 sections，context 必须用 `renderContextSections()` 验证，拿前者测后者会得到假的「通过」。

仍未覆盖：

- 「组装抛错 → 该轮请求失败 → 会话不可用」的**完整会话级**验证没做——那需要一条含 `{{` 的常驻记忆加一次真实模型请求。已复现的是组装阶段抛错这一环。
- DSH 0.1.6 及以后是否提供 `interpolate` 开关未核实。若提供，§5.1 可换成开关；本方案仍可作为不依赖版本探测的兼容路径。
- `neighborNotice` 的输入是文件系统目录名。含 `{{` 的目录名是理论可能、实际罕见；本方案把它与其余三条一并覆盖，未单独评估。
